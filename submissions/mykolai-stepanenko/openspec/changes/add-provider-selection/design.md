# Design

## Context

Мотивація описана в proposal.md. Поточний стан:
- `BitcoinPriceService::current()` перебирає `list<BitcoinPriceProvider>` з конфігу `services.bitcoin_price.providers` (зараз CoinGecko, потім Coinbase). Кожен провайдер має `name()`.
- `Api/BitcoinPriceController` викликає `current()` і мапить `BitcoinPriceUnavailableException` у 503.
- FormRequest-ів у проєкті ще немає (`app/Http/Requests` відсутній).
- `BtcPriceWidget.vue` робить `fetch('/api/btc-price')`, у ньому є стани loading/error і кнопка «Оновити».

Рішення користувача: за замовчуванням лишається поточний ланцюжок; для обраного провайдера fallback немає, збій дає помилку.

## Goals / Non-Goals

**Goals:**
- Явний вибір провайдера без змін поведінки за замовчуванням і формату відповіді.
- Новий провайдер з'являється у валідації API автоматично, щойно його додали в конфіг.

**Non-Goals:**
- Кілька цін одночасно (порівняльна таблиця), збереження вибору між перезавантаженнями, окремі endpoint-и на кожного провайдера.
- Динамічний список кнопок з API. У віджеті два провайдери, тож список кнопок задано прямо в коді (YAGNI). Нового провайдера доведеться додати у віджет вручну.

## Decisions

- **API: query-параметр, а не нові роути.** `GET /api/btc-price?provider=coinbase` зберігає один ресурс і формат відповіді. Альтернативу `/api/btc-price/{provider}` відкинули: це той самий ресурс з фільтром, і роут з параметром у шляху важче зробити необов'язковим.
- **Сервіс:**
  - `fromProvider(string $name): BitcoinPrice` знаходить провайдера за `name()` і викликає його один раз. Будь-який `Throwable` провайдера обгортається в `BitcoinPriceUnavailableException` і пишеться в лог як warning, так само як у `current()`. Провайдера з такою назвою немає — теж `BitcoinPriceUnavailableException`. Це захист, бо до сервісу невідома назва не дійде завдяки валідації.
  - `providerNames(): list<string>` повертає назви в порядку конфігу.
  - `current()` не змінюється (OCP), fallback лишається тільки там.
  - Спільну частину (виклик провайдера → DTO) виносимо в приватний метод, щоб не дублювати (DRY).
- **Валідація в HTTP-шарі:** новий `App\Http\Requests\BtcPriceRequest` (`make:request`) з правилами `provider` → `['sometimes', 'string', Rule::in($service->providerNames())]`. Сервіс інжектиться в `rules()` через контейнер. Так валідація живе там, де її вимагає правило шарів, а список провайдерів не дублюється в коді. Laravel сам дає 422 для `api/*` у JSON (`shouldRenderJsonWhen` в `bootstrap/app.php`).
- **Контролер:** `$request->validated('provider')`: якщо є, викликає `fromProvider()`, якщо немає — `current()`. Мапінг 503 і формат 200 (з `JSON_PRESERVE_ZERO_FRACTION`) лишаються.
- **Frontend (`BtcPriceWidget.vue`):**
  - константа `providers = [{ id: null, label: 'Авто' }, { id: 'coingecko', label: 'CoinGecko' }, { id: 'coinbase', label: 'Coinbase' }]` і `ref selectedProvider = null`;
  - `loadPrice()` будує URL через `URLSearchParams`, щоб параметр додавався тільки для обраного провайдера;
  - кнопки — сегментована група з `aria-pressed`;
  - повідомлення про помилку залежить від вибору: «Ціна тимчасово недоступна» для «Авто», «Ціна від {label} тимчасово недоступна» для конкретного провайдера;
  - кнопки не блокуються під час loading, але повторне натискання на активну кнопку просто оновлює ціну.
- **Гонка запитів:** якщо швидко натиснути кілька кнопок, пізня відповідь може перезаписати новішу. Кожен виклик має лічильник `requestId`, і відповідь, що прийшла не від останнього запиту, ігнорується. Так обходимось без AbortController (KISS).

## Risks / Trade-offs

- [Кнопки у віджеті задані в коді і розходяться з конфігом] → назви в API валідуються за конфігом, тож застаріла кнопка дасть 422 і віджет покаже помилку. Це описано в Non-Goals.
- [Користувач частіше звертається до CoinGecko вручну і впирається в rate limit] → як і раніше, тоді повертається 503. Користувач бачить помилку і може обрати інше джерело.
- [JS-поведінку автотести не покривають] → ручний smoke. Якщо підключено Claude in Chrome, smoke робить агент.
